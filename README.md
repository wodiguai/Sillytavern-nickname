# Address Ledger｜称呼关系簿

一个不依赖服务器插件的 SillyTavern UI 扩展，用于按聊天记录角色之间的称呼惯例，并把精简状态注入下一轮生成提示。

## 当前版本（0.1.0）

- 按聊天保存，数据位于 `chatMetadata.addressLedger`。
- 明确记录“使用者 → 被称呼者”，不会反向套用。
- 支持正式称呼、昵称、日常爱称、私密爱称、家庭/工作/禁用称呼。
- 分别记录接受度、熟悉度、情绪显著度与抗习惯化程度。
- 内置“稀少但高冲击”私密爱称预设。
- 区分私人、公开等适用场景和获准使用者。
- 可扫描当前聊天中某个称呼由指定使用者出现的次数，用于同阶段反应衰减提示。
- 自动在指定聊天深度注入精简状态和连续性规则。
- 支持每个聊天的 JSON 导入、导出。

第一版不会调用模型自动修改接受度，避免把玩笑、沉默或叙述误判成永久许可。接受度与状态由用户确认。

## 安装

### 手动安装

1. 把整个 `address-ledger` 文件夹复制到 SillyTavern 的下列目录之一：
   - 当前用户：`data/<user-handle>/extensions/address-ledger`
   - 所有用户：`public/scripts/extensions/third-party/address-ledger`
2. 重启 SillyTavern，或刷新页面。
3. 打开“扩展”面板，找到“Address Ledger｜称呼关系簿”。

文件夹名称应保持为 `address-ledger`，否则模板路径无法匹配。

## 使用

1. 进入目标聊天。
2. 打开扩展面板并展开“Address Ledger｜称呼关系簿”。
3. 点击“新增称呼”。
4. 填写使用者、被称呼者和称呼内容。
5. 普通称呼可直接调整状态与滑块；私密称呼可点击“套用‘稀少但高冲击’”。
6. 保存后查看“注入预览”。

如需快速试用，可以导入 `examples/private-address.example.json`，再把示例中的角色名与称呼改成当前聊天内容。

推荐保持注入位置为 `System / Depth 1`。如果已有其他 Depth 1 规则也可以同时使用。

## 数据语义

- **接受度**：被称呼者是否允许指定使用者这样称呼。
- **熟悉度**：被称呼者是否已经习惯听见。
- **情绪显著度**：该称呼承载的感情重量。
- **抗习惯化**：即使熟悉后，情绪反应是否仍不易消退。

因此，“已经接受并熟悉”不等于“没有反应”。私密爱称可以拥有很高接受度、熟悉度和情绪显著度，同时通过稀少频率保持冲击力。

## 开发与检查

扩展没有第三方依赖。需要 Node.js 18 或更高版本运行本地检查：

```powershell
npm run check
npm test
```
